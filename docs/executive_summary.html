Executive summary — how to make a submission

Five steps, about two minutes. Everything here is taken from the official pages linked in the Audit; the upload form's wording is quoted from the project owner because the form is behind a DrivenData login.

TL;DR

  1. Download a file from the Home page (recommended: Upload #1).
  2. Check it in the checker below (optional but free).
  3. Open the competition Submit (sidebar) Make new submission.
  4. File to submit: choose the .tif (or the ZIP). Note (optional): paste the note from the card.
  5. Submit, wait for the public score, then record it.

Pre-upload checker (runs in your browser)

Drop a .tif here or choose a file

Nothing is uploaded; the file is read locally. ZIPs: unzip first.

If DrivenData says “Predicted values must be in range [0, 1]”

  1. Drop the exact uploaded file into the checker. A red ✖ on “No NaN/Inf inside the footprint” or “Every footprint value within [0, 1]” names the fault. NaNs inside the footprint are a likely cause: all 19 input layers have 3,061–3,073 invalid pixels inside the scored area (flag F05), and models propagate them.
  2. If everything is ✔, the file meets every published rule. We could not reproduce the error with any file ever published on this site (flag F13), and the repositories behind the group's scored entries publish files in every encoding (NaN-outside and zero-outside, LZW and deflate, striped and tiled) — assuming the published file is what was uploaded.
  3. Try the all-finite fallback (same in-footprint prediction, zeros outside). It carries the same content id, so it is not a new experiment.
  4. Still rejected? Email info@drivendata.org (technical help, per the forum header) with the file name, SHA-256, time and a screenshot. Rules questions: gemsprize@nlr.gov.
  5. Do not rescale or edit values to “get it through”: that changes the prediction. Whether a rejected upload counts against the weekly allowance is not stated in the sources read; ask DrivenData.

Rules that affect how you use the slots

  • Three uploads per rolling 7 days per entity (rules §3.2/3.4; staff: forum 11524 #2).
  • One final submission per entity. Choose it before Dec 3, 2026 23:59 UTC, without seeing private-set scores; team members cannot each submit a separate final.
  • Accounts are personal (Terms of Use). Do not pool accounts to multiply the limit; see F08.
  • Disclose generative-AI use in any prize narrative (rules §3.2).
  • Known-fault pixels are masked; a prediction near a known fault but far from a new fault is fully penalised (staff).

After the score appears

Record it so the next session can learn from it (this is the one step that cannot be automated — DrivenData's Terms of Use forbid bots, and scores live behind login):

python scripts/record_score.py <candidate-key> <score> (candidate keys: h18-3a, h16-1, sgmc-gap; the score is whatever DrivenData shows) updates registry/submissions.json and the site data; then commit. The A/B pair (#1 vs #2) is the first calibration of whether the holdout proxy predicts the public score.
