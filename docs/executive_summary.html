Strict submission format (from DrivenData)

  • Single-band 32-bit float GeoTIFF.
  • Same CRS (EPSG:32611), 100 m resolution, bounds and grid as the template.
  • Prediction values in the evaluation footprint must be within [0,1].
  • Pixels outside the bounds must be null/NaN.
  • DrivenData accepts a single .tif or a .zip containing a single GeoTIFF.

How to make a submission

  1. Choose one format-validated GeoTIFF from the main hub. Do not treat NaN/zero outside-footprint twins as distinct predictions.
  2. Use a unique name and short comment that accurately identifies the method and does not claim a score that is unknown. The note above can be copied; edit the ID/comment when choosing a genuinely different experiment.
  3. Open the DrivenData submission page ↗, select the .tif (or accepted single-TIFF ZIP), paste the comment, and submit.
  4. After the public score appears, record it with filename, SHA-256, score, timestamp, and experiment note in the project audit. Check the official page/account for current submission limits before upload.
About the previous “Predicted values must be in range [0, 1]” error: without the rejected file, the exact cause cannot be established. An in-footprint NaN, an actual value below 0 or above 1, or another input/format issue may cause rejection. The local validator catches in-footprint NaN and out-of-range values; the pipeline must sanitize source-feature NaNs before inference. The validator does not prove that a file will score well.
