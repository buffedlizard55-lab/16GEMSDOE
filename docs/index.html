Line-by-Line Verification & Irregularity Flags

3. Irregularities Flagged for Manual Review & Official Verified Data Sources

FLAG-01 (Official Sample Submission Leak / Contradiction): On the official DrivenData problem description page (page/967), the organizers state that sample_submission.tif "is an uninformative baseline that predicts total fault absence". Line-by-line pixel verification in scripts/prepare_data.py (saved in evidence/data_verification.json) proves that sample_submission.tif is in fact bit-for-bit identical to (labels.tif > 0) inside the 5,167,373-pixel footprint (60,988 positive pixels, 0 differing pixels!). Furthermore, our group's live submission 8GEMSDOE (052688ea, which took max(ens12, sample_submission)) scored the exact same 0.1563 as GEMSDOE1 (7f00890a), proving that those 60,988 known catalogue pixels are masked out of both $\text{TP}$ and $\text{FP}$ on the live leaderboard.
FLAG-02 (In-Footprint Feature NaN Traps in training_features.tif): While sample_submission.tif defines 5,167,373 finite evaluation pixels, training_features.tif contains 1,521 internal NaN pixels across 18 bands and 1,533 internal NaN pixels in Band 6 (tc), totaling 3,061 footprint pixels with at least one NaN feature. Any pipeline that fails to impute those 3,061 pixels before inference emits in-footprint NaNs and triggers DrivenData's "Predicted values must be in range [0, 1]" error. Our src/gems/validator.py enforces zero in-footprint NaNs and strict [0.0, 1.0] clipping on every output file.
FLAG-03 (Cross-Fold Leakage Trap When Evaluating Longitude-Stripe OOF CNN Rasters on Quadrant Splits): The pre-computed context_detector_prob_*.tif rasters from GEMSDOE1 were trained on 4 longitude stripes across full labels.tif. Evaluating a second-stage model that includes context_detector_prob_*.tif on a 4-quadrant split inflates apparent quadrant Dense DTI to 0.41895 because 75% of each longitude stripe's training labels overlap each quadrant. We flagged and eliminated this leakage in our 4-quadrant holdout evaluation (scripts/run_spatial_holdout_and_build.py) by evaluating H16-1 through H16-5 strictly on leak-free physical features trained out-of-quadrant with a 1.5 km buffer.
