Submission checks and known irregularities

  • The official competition page requires EPSG:32611, 100 m resolution, matching bounds, a single float32 layer, values in [0,1], and null/NaN outside bounds. Review it before every upload.
  • The prior “Predicted values must be in range [0, 1]” rejection cannot be diagnosed exactly without the rejected file. In-footprint NaNs can trigger the check, but genuinely out-of-range values or other issues are also possible.
  • The official page describes the sample submission as an all-absence baseline. The local bridged sample has 60,988 positive pixels, exactly matching the positive mask in the local labels file. This is a confirmed local-file property, but the private competition download was not independently retrieved here; the cause remains unresolved.
  • The local data came from the team’s public hash-pinned GitHub bridge because the DrivenData data tab requires login. Matching hashes establish consistency with the bridge, not independent provenance from DrivenData.
  • A former README citation for GeoDAWN DOI 10.5066/P9Z6SA1Z was incorrect; USGS lists GeoDAWN DOI 10.5066/P93LGLVQ. A previously cited lidar ScienceBase record returned Not Found; see the source register for current official links.
